# 《迷雾突围》UI 设计规格（MVP）

## 1. 设计目标

1. 一眼可理解：资源、风险、回合与行动关系清晰
2. 一眼有吸引力：非极简、具有“迷雾压迫 + 科技扫描”质感
3. 单手操作友好：核心按钮集中底部、触达区域充足

---

## 2. 信息架构

## 2.1 首页 HOME

```
┌──────────────────────────┐
│ 标题 + 卖点文案           │
│ 规则摘要卡                │
│ [开始突围]                │
│ [玩法说明]                │
│ (可展开说明面板)          │
└──────────────────────────┘
```

目标：在 3 秒内传达“短局策略 + 环境会适应”。

## 2.2 对局页 BATTLE

```
┌──────────────────────────┐
│ 回合与进度条              │
│ 4 资源卡片（2x2）          │
│ 事件结果区                │
│ 战术画像模块              │
│ 行动按钮 x 3（底部纵向）   │
└──────────────────────────┘
```

优先级：
1) 行动选择 2) 资源与进度 3) 事件与画像反馈

## 2.3 结算页 RESULT

```
┌──────────────────────────┐
│ 成功/失败大标题            │
│ 资源结果面板              │
│ 系统观察报告              │
│ 可读性反馈（界面清晰/偏花）│
│ [再来一局]                │
└──────────────────────────┘
```

---

## 3. 组件规范

## 3.1 行动按钮

- 高度：约 110~120（逻辑像素）
- 圆角：18
- 左对齐主文案 + 次级描述
- 状态：
  - 默认：蓝色渐变 + 外发光描边
  - 按压：降低亮度、描边减弱
  - 不可用：灰化

## 3.2 资源卡片

- 2x2 布局
- 数值采用高亮发光字体
- 风险 >= 7 时切换危险色（红）

## 3.3 战术画像模块

- 标题：战术画像
- 行：风格标签 + 环境状态
- 行：短文案（可解释当前局势）

---

## 4. 交互反馈节奏

1. 点击行动 -> 立即更新资源
2. 同帧或下一帧显示事件反馈文案
3. 战术画像按更新周期变更（每 2 回合）
4. 终局进入结果页，无多余等待

---

## 5. 可读性规则

1. 核心数字对比度 >= 4.5:1
2. 背景动效不覆盖正文区域
3. 正文单行长度限制（防阅读疲劳）
4. 事件文本采用自动换行

---

## 6. 文案语气规范

- 简短
- 冷静
- 克制
- 带观察感，不说教

推荐：
- 迷雾开始记录你的补给偏好。
- 你推进过快，前方压力正在提前聚集。
- 你保持了安全，但撤离窗口正在缩小。
